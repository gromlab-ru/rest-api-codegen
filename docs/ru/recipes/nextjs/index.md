# Next.js App Router

В Next.js запросы могут выполняться в браузере или на сервере. В примерах эти два варианта разделены, чтобы случайно не передать серверные секреты в клиентский код.

## Подключить API

- [Полный клиент](./full-client.md) - `POST` из клиентского компонента и `GET` из серверного.
- [Частичный клиент](./partial-client.md) - только методы, нужные конкретному разделу приложения.
- [Ручной клиент без OpenAPI](./manual-client.md) - одни операции для браузера и сервера.
- [Исправление неверно описанного метода](./broken-endpoints.md) - одна исправленная версия для обоих окружений.

## Работать с данными в клиентских компонентах

- [TanStack Query](./tanstack-query.md).
- [SWR](./swr.md).

Для обычного `GET`-запроса в серверном компоненте дополнительная библиотека кеширования не нужна.

## Настроить авторизацию

- [JWT из `localStorage`](./jwt-local-storage.md) - только для клиентских компонентов.
- [Cookie-аутентификация в браузере](./cookie-auth.md).
- [Cookie-аутентификация на сервере](./ssr-cookie-auth.md).

## Где выполняется код

| Место | Как создаётся клиент |
| --- | --- |
| Клиентский компонент | Один клиент для текущей вкладки браузера |
| Серверный компонент без данных пользователя | Общий серверный клиент без пользовательских cookie |
| Серверный компонент с авторизацией | Новый клиент для каждого входящего запроса |

## Что выбрать

| Потребность | Решение |
| --- | --- |
| Нужна большая часть API | [Полный клиент](./full-client.md) |
| Разделу приложения нужно несколько методов | [Частичный клиент](./partial-client.md) |
| Клиентский хук вызывает один метод | [TanStack Query](./tanstack-query.md) или [SWR](./swr.md) |

Если клиент поставляется отдельным npm-пакетом, используйте раздел [Пакет](../package/index.md).
