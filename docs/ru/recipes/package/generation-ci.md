# Воспроизводимая генерация в CI

Чтобы генерация давала одинаковый результат локально и в CI, укажите точную версию генератора, используйте одну основную версию Node.js и храните OpenAPI в локальном JSON-файле.

## Команды в `package.json`

```json
{
  "scripts": {
    "generate": "npx --yes @gromlab/rest-api-codegen@5.2.0 --input ./openapi/pet-store.openapi.json --output ./src",
    "clean": "node --input-type=module -e \"import { rmSync } from 'node:fs'; rmSync('dist', { recursive: true, force: true })\"",
    "compile": "npm run clean && tsc -p tsconfig.json",
    "build": "npm run generate && npm run compile"
  }
}
```

Устанавливать `@gromlab/rest-api-codegen` в `devDependencies` только ради CLI не требуется. Версия уже зафиксирована в команде `generate`, поэтому её обновление будет видно в истории изменений.

## Проверка актуальности файлов в GitHub Actions

```yaml
name: Проверка сгенерированного клиента

on:
  push:
  pull_request:

jobs:
  generated-sdk:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - run: npm ci
      - run: npm run generate

      - name: Проверить сгенерированные файлы
        shell: bash
        run: |
          changes="$(git status --porcelain=v1 --untracked-files=all -- src)"
          if [[ -n "$changes" ]]; then
            printf '%s\n' "$changes"
            exit 1
          fi

      - run: npm run compile
```

`npm ci` устанавливает зависимости пакета. Затем `npx` запускает именно ту версию генератора, которая указана в `package.json`.

Одного `git diff --exit-code` недостаточно: команда не замечает новые файлы, которые ещё не добавлены в Git. Использованный вариант `git status` находит изменённые, удалённые и новые файлы.

## Правила воспроизводимости

- Указывайте точную версию `@gromlab/rest-api-codegen` в `npx`-команде.
- Фиксируйте основную версию Node.js, требуемую генератором.
- Храните `package-lock.json` в Git и устанавливайте зависимости через `npm ci`.
- Каталог `src` должен находиться под контролем версий, если CI проверяет сгенерированные файлы.
- Предпочитайте локальный JSON-файл: содержимое по URL может измениться между сборками.
- YAML не поддерживается.
- Не запускайте две генерации одновременно в один каталог: блокировки файловой системы нет.
- Не храните ручной код внутри каталога генерации.
- Всегда проверяйте код завершения команды, даже если старые файлы остались на месте.

Одинаковая спецификация, версия генератора и версия Node.js дают стабильный результат без временных меток. Перестановка полей или маршрутов в самой OpenAPI всё равно может изменить порядок файлов и строк.

Закрытую удалённую спецификацию лучше скачать отдельным шагом CI, настроив авторизацию, ограничение времени и повторные попытки. После этого передайте генератору локальный файл; при необходимости дополнительно проверьте его контрольную сумму.

Перед запуском `tsc` очищайте `dist`, иначе там могут остаться JavaScript-файлы и декларации уже удалённых операций.

Если пакет содержит ручные исправления, генератор пишет в `src/generated`. CI проверяет этот каталог, а затем собирает вместе с ним управляемые точки входа и ручные операции. См. [рецепт смешанного пакета](./generated-with-corrections.md).
